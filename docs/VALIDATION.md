# 验证范围

记录日期：2026-10-08。这里是移除设备名称和本机路径后的事实摘要，不包含原始媒体日志或真实歌曲截图。

## 实际设备与桌面观测

已测试环境为 Windows 11 x64（10.0.26200）、iOS 26、网易云音乐并开启锁屏歌词。手机型号未确认；没有扩展为所有 iPhone、播放器或蓝牙适配器的兼容性结论。

| 观测 | 证据级别与结果 |
| --- | --- |
| AMS 发现与媒体通知 | 实际读到播放器、媒体文字、状态、位置和时长；持续状态通过通知接收，定时 GATT 读取为 0 |
| 手机链接进程退出后的播放 | 既有 AMS 连接发送播放，手机状态开始前进；使用者确认手机恢复了音乐 |
| 暂停位置对照 | 手机 3:05，AMS 185.197 秒 |
| 手机跳转后暂停对照 | 手机 1:43，AMS 103.280 秒 |
| 透明浮窗 | 实际检查像素透明、点击穿透、热键注册、样式切换和设置保存；没有把热键消息测试当作实体键盘测试 |
| 任务栏 | 主屏 125%、副屏 150% 实际挂靠，原生父窗口与 WS_CHILD 验证；使用者确认悬停按钮出现并可点击；模式切换复用媒体连接 |
| 进度条 | 两种视图实际检查为只读；有效位置／时长缺失时隐藏 |
| 单文件打包 | 实际直接启动、从其他工作目录启动、图标提取与托盘加载、重复启动退出第二个进程、恢复设置 |
| 手机离开后返回 | 离开期间连接失效，返回并再次建连后 25 秒收到 4 次媒体通知，无新增断线；使用者反馈运行正常 |

这些位置对照只确认整秒显示一致。未测量手机通知延迟、实际声音延迟或毫秒级同步。单文件使用自包含配置；测试电脑原本有 .NET，没有在干净机器验证免安装。

## 本轮源码整理检查

重命名和目录整理后的主项目与控制台工具已在本地构建，29 项逻辑检查通过。这些检查覆盖 AMS 解析、非法锚点、暂停、歌词与曲目变化、任务栏空位及启动参数；不访问蓝牙。

整理后的便携 EXE 已用独立示例模式实际启动，载入图标并生成两张原创示例 PNG，随后正常关闭；示例日志中的 AMS 建连数和手机控制命令数均为 0。原有实例保持运行。控制台帮助和缺失播放器时返回失败的行为也已实际检查。

真实手机证据来自整理前同一套 AMS 逻辑，不能当作整理后新 EXE 的再次端到端验证。GitHub Actions 配置只在本地准备，尚未上传或运行。

## v0.1.0 发布候选复查

便携 profile 更新为 .NET / Windows Desktop Runtime 10.0.12。源码再次编译为 0 警告、0 错误，29 项逻辑检查通过。运行库许可和通知既随 ZIP 提供，也嵌入独立 EXE。

最终候选从发布 ZIP 解压后，在不同工作目录实际启动，环境日志确认使用内置的 .NET 10.0.12。成功订阅 AMS 并一次性读到播放器、媒体文字、暂停状态、有效位置与时长；该次手机暂停期间没有新的 EntityUpdate 媒体通知，不能把初始补读计作持续通知。更新运行库后的前一个候选实际收到 6 次 EntityUpdate；最终候选额外变化仅为嵌入许可资源。

最终候选的浮窗和任务栏进度都通过 UIA 确认为只读，任务栏原生 WS_CHILD 与边界检查通过。浮窗／任务栏往返切换复用同一条 AMS 连接；第二次启动正常退出并唤出已有实例。此次没有发送手机播放控制，不替代前面的使用者手机响应对照。

检查时手机链接后台进程存在，因此不能作为独立冷启动证据。测试电脑没有安装 10.0.12 的共享运行库，但已有旧版 .NET；仍未在完全无 .NET 的干净机器测试。

发布 ZIP 使用明确的 13 个文件条目，EXE 与独立附件哈希一致，SHA-256 核对通过，没有个人设置、原始媒体日志或桌面截图。EXE 未数字签名。发布说明和 GitHub Actions 的附件打包步骤已准备，未上传、创建标签或发布 Release。
